## Где хуже всего и почему

**air-photo, 12,99.** Фотография лежит в Display P3. Браузер конвертирует её в
sRGB корректно (176,6 против наших 176,2 по среднему), а Figma рендерит ярче и
теплее (186,8). Это цветовой профиль, а не вёрстка. Решение не принято.

**entry, 5,10 и voices, 4,90.** Длинные фото под текстом: расхождение копится в
растеризации, геометрия при этом нулевая.

## Что осталось

1. **Адаптив 390/768** — не начат. В файле только 1440.
2. **`/ds`** — страницы со всеми вариантами компонентов нет.
3. **Эффекты** — `background-blur` и тени в CSS не перенесены: шапка держится на
   полупрозрачном фоне, но без размытия.
4. **`air-photo`** — разобраться с Display P3: либо запечь тон под рендер Figma,
   либо принять расхождение.
5. **Вес ассетов** — `public/img` 6,7 МБ; пережатие отложено решением владельца.

## Команды

```bash
npm run intake                                     # снимок живого файла
npm run document                                   # полный дамп: переменные, стили, узлы
npm run export -- <nodeId> --name <slug>           # спека + кроп + ассеты
npm run ds:tokens                                  # токены и типографика
npm run build
npm run measure -- design/figma/pages/home/hero/spec.json
npm run shot -- .hero .screens/hero.png 1440
npm run compare -- <crop.png> <shot.png>
npm run previews && npm run structure              # опубликовать на /structure.html
npm run page -- --page home --url /                # сверить страницу целиком
npm run status                                     # таблица секций из артефактов
npm run verify                                     # экспорт ↔ мост ↔ API ↔ .fig
```

Сборка и замер, запущенные параллельно, идут через `node tools/lock.mjs "<команда>"`:
они пишут и читают общий `dist/`.
