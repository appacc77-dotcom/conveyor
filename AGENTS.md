# AGENTS.md — Syntonia

Читается агентом до любых изменений. Здесь: что является истиной, что можно
трогать и когда работа считается сделанной. Если правило мешает — остановись и
спроси, а не обходи.

## 0. Проект и его состояние

Syntonia — сайт по макету Figma: Astro + обычный CSS + данные, без React,
Tailwind и CMS. Ценность проекта — не сайт, а проверяемый конвейер
Figma → спецификация → компоненты → страницы → ворота.

**06.11.2026 проект перезапущен.** Готовый сайт (48 компонентов, 13 страниц)
удалён: он был собран без ворот, и приёмка показала escape rate 33% — 5 дефектов
из 15 карточек после «готово». Удалённое восстановимо: git-тег
`pre-reset-2026-11-06`. Подробности — [`STATUS.md`](STATUS.md).

**Объём — только страница Home.** Остальные страницы файла (practice, library,
masters, method, booking, quiz) не собираются: решение владельца от 06.11.2026.
Секции этих страниц выгружены и лежат в `design/figma/pages/**`, но компонентов
для них не делаем. Если задача требует блок с другой страницы — это вопрос к
владельцу, а не расширение объёма.

Актуальное состояние — [`STATUS.md`](STATUS.md). Фазы P0 (Ingest), P1 (Reality)
и G0 закрыты по живому файлу; идёт P4 — первый блок `hero` собран и замерен.
Процесс — [`docs/system/PROCESS.md`](docs/system/PROCESS.md) (P0–P7, G0–G3).
Роли и контракты — [`docs/system/README.md`](docs/system/README.md).

## 1. Источники истины (по приоритету)

**Главный источник — мост `figma-agent` к открытому файлу.** Из него берётся всё,
что попадает в вёрстку: спеки, кропы, ассеты, токены, стили.

Два вспомогательных источника — **только для сверки и поиска**, не для сборки:

| Источник | Чем полезен | Чем не годится |
|---|---|---|
| Мост (`figma-agent`) | всё, что видит плагин: свойства узлов, переменные, варианты, экспорт | требует открытого Figma и живого соединения |
| REST API (`api.figma.com`) | версия файла, проверка страниц, фреймов и секций без приложения | только опубликованные стили и компоненты, лимит запросов (429) |
| `.fig` (архив) | независимая сверка картинок и текстов, работает офлайн | снимок на дату, может быть от другого `fileKey` |

Если мост и сверка расходятся — прав мост, а расхождение записывается в
`docs/decisions.md`. Сверка не чинит вёрстку, она показывает, что что-то
изменилось в файле или потерялось при выгрузке.

1. `docs/decisions.md` — принятые решения. Выше кода.
2. Живой файл: `figma-agent` к открытому документу (`fileKey` в
   `design/figma/project.json`).
3. `design/figma/live/*.json` — снимки файла: структура, дизайн-система, реальность,
   полный дамп `document.json`.
4. `design/figma/pages/<page>/<section>/spec.json` — числа секции для замера (P2).
5. `design/figma/pages/<page>/<section>/crop.png` — эталон, экспортированный с узла (P3).
6. Код `src/` — реализация, не истина.

Два правила важнее остальных:

- **Число без `fileKey` — не число.** Он лежит в `design/figma/project.json`.
- **Число без замера — не число.** Геометрия проверяется `npm run measure`,
  пиксель — `npm run compare`; «на глаз сошлось» не считается.

## 2. Принципы переноса

Действуют всегда, в любом режиме.

1. **Единица работы — компонент, единица приёмки — тоже.** Страница — композиция,
   а не поле для подгонки.
2. **Эталон — рендер узла, не дерево.** Кроп снимается с живого узла
   (`figma-agent export-png`) и сверяется снимком страницы.
3. **Компонент не знает, где стоит.** Ни `width`, ни `margin`, ни `font-size` под
   конкретное место вызова. Если размер не сошёлся — виноват шрифт, трекинг или
   паддинг, а не место вызова.
4. **Только токены.** Hex и «похожий» px в компоненте — дефект. Токены — из
   сгенерированного файла, не набранные руками.
5. **Имена 1:1 с Figma.** Набор `btn-primary` → `btn-primary.astro`. Новые
   компоненты библиотеки — в `src/components/ds/`.
6. **`data-figma-node`** на каждой секции: без него нечего сравнивать.
7. **Не додумываем.** Нет состояния, текста, цены или отступа в макете — значит
   их нет. Вопрос — в `decisions.md`, а не в код.
8. **Мобилка — отдельно.** Макеты 390/768 заказаны. До них адаптив — инженерный
   слой (нет переполнения, тап-таргеты ≥ 44 px), и он не называется «по макету».
9. **Контент-заглушки помечаются.** Цены и длительности из файла не подтверждены
   заказчиком: они допустимы в вёрстке и блокируют публикацию, а не карточку.

## 3. Границы

- **Runtime:** `src/`, `public/`, `astro.config.mjs`, `tsconfig.json`,
  `package.json`. Публикуется `dist/`.
- **Не трогать без карточки:** `docs/system/**` (процесс), `package.json`
  (зависимости), `design/figma/live/**` (снимки файла).
- **Только чтение, генерируемое:** `src/styles/tokens.css`,
  `src/styles/typography.css` (пишет `npm run ds:tokens`), `design/figma/pages/**`.
- **Общий слой** — `src/styles/base.css`, шапка, подвал — меняется отдельной
  карточкой, а не «попутно».
- **Новые зависимости** — только с согласованием.
- **Git:** один коммит — одна мысль. `push`, `reset --hard`, `rebase` — не без
  просьбы.

## 4. Задача = карточка

Одна карточка — один запуск. В карточке: `id`, единица (`component` / `section`),
узел Figma, `figma_version`, срез `spec`, кроп, `files:`, команда приёмки,
`content_status`.

- работа начинается только при заполненном Definition of Ready
  ([шаблон](docs/system/templates/card.md));
- меняются только файлы из `files:`; нужен ещё файл — `blocked`, а не расширение
  правки;
- по завершении — отчёт с числами ([шаблон](docs/system/templates/report.md)),
  статус `review`, не `done`;
- карточку в `done` переводит приёмка, не автор.

Доска — внешний DSH Kanban (`DSH_BOARD_URL` или прокси `/kanban`). Перед работой:
`kanban_board { next: true }`; закончил — `kanban_card { action: "move", cardId,
column: "review" }`. `board.json` руками не править: плагин проверяет DoR и
ведёт историю. Как это устроено — [`docs/system/KANBAN.md`](docs/system/KANBAN.md).

## 5. Фазовая дисциплина

Фазы P0–P7 последовательны. **Отсутствие инструмента — причина его сделать, а не
обойти.** Прошлый прогон обошёл именно так: «ворот пока нет, соберём секции» —
и получил 13 страниц без единой проверки.

Пока фаза не закрыта, запрещено начинать следующую:

| Фаза | Закрывается | Сейчас |
|---|---|---|
| P0 Ingest | `design/figma/live/*.json` + `fileKey` | **готово** |
| P1 Reality | числа по файлу (масштабы, ширины) | **готово** |
| G0 | 0 открытых 🔴 в `decisions.md` | **закрыт** |
| P2 Resolve | `design/figma/pages/<page>/<section>/spec.json` | идёт |
| P3 Model | токены, кропы | готово для hero |
| P4 Components | G1: `measure` зелёный по каждому компоненту | идёт: hero |

**Не перескакивать:** следующая фаза начинается, только когда у предыдущей есть
артефакт на диске. «Соберём одну главную, чтобы посмотреть» — не аргумент.

## 6. Проверки

```bash
npm run intake                                 # снимок живого файла; exit 1 при чужом файле
npm run document                               # полный дамп: переменные, стили, все узлы со свойствами
npm run export -- <nodeId> --name <slug>       # кроп + ассеты + spec.json секции
npm run ds:tokens                              # токены и типографика из живого файла
npm run build                                  # dist/
npm run shot -- .hero .screens/hero.png 1440   # снимок элемента
npm run measure -- design/figma/pages/home/hero/spec.json   # геометрия по data-figma-node
npm run compare -- <crop.png> <shot.png>       # пиксель, без внешних зависимостей
npm run previews                               # снять собранные секции Playwright'ом
npm run structure                              # пересобрать /structure.html из артефактов
npm run stamp                                  # отпечатки содержимого и версия облака в спеки
npm run verify                                 # сверка: экспорт ↔ мост ↔ API ↔ .fig
```

**Проверка актуальности.** В каждой спеке есть `fingerprint` — контрольная сумма
содержимого секции, и `cloudVersion` — версия файла на сервере в момент снятия.
`npm run verify` заново читает секции мостом и сравнивает отпечатки: если
разошлись, экспорт устарел. Недоступность API или отсутствие `.fig` — пропущенная
сверка, а не провал.

`measure` — ворота геометрии: элемент с `data-figma-node` сверяется с узлом из `spec.json`
по абсолютным координатам от корня секции. Красные, если расхождение больше 1 px,
если у узла глубины ≤ 2 нет своего элемента или если атрибут ссылается на узел вне спеки.
`compare` — сигнал регрессии, не критерий приёмки: текст растеризуется по-разному,
фон и заливки совпадают. Ориентир: hero — средняя 1,76, пикселей > 16 — 0,98 %.

**Любое утверждение о соответствии подкрепляется числом и командой**, которая это
число получила. Скриншот без числа — впечатление, а не проверка.

**Публикация обязательна.** Секция не считается сданной, пока её нет на
`/structure.html` с парой «Figma / сделано» и числами: `npm run previews` →
`npm run structure`. Страница собирается из артефактов, поэтому расходиться с
кодом не может — но только если её пересобирать.

## 7. Стоп-условия

Остановиться и вернуть `blocked` с причиной, если:

- нет кропа или спеки по единице, либо `fileKey` живого файла не совпал с
  `project.json` (работать по чужому файлу нельзя);
- в `decisions.md` открыт 🔴 по этой единице;
- spec расходится с кропом (тогда чинится spec, а не вёрстка);
- нужен файл вне `files:`;
- три итерации подряд красные по одному и тому же числу;
- чтобы пройти проверку, нужно нарушить §2 — например, вписать ширину;
- задача требует фазы, которая не закрыта.

В отчёте: что отсутствует или противоречит, варианты решения, что уже проверено.
Решает владелец.

## 8. Документы: две версии

Правило проекта: у документа две версии — человеческая (что это значит, без имён
свойств) и агентская (id, свойства, было → стало).

- [`TUTORIAL.md`](docs/TUTORIAL.md) — учебник: от пустой папки до собранного блока;
- [`ARCHITECTURE.md`](docs/ARCHITECTURE.md) — устройство и почему так;
- [`FIGMA-ISSUES.md`](docs/FIGMA-ISSUES.md) — что поправить в макете, с числами;
- [`decisions.md`](docs/decisions.md) — принятые решения, append-only;
- [`RUNBOOK.md`](docs/RUNBOOK.md) — холодный старт на новом сайте;
- `reports/**` — числа и вердикты.

## 9. Definition of Done

**Компонент:**

- [ ] имя = имя набора Figma, API = пропсы Figma;
- [ ] нет размеров, зависящих от места вызова;
- [ ] только токены;
- [ ] `data-figma-node`;
- [ ] есть в `/ds` во всех вариантах;
- [ ] кроп-дифф в пороге;
- [ ] **движение:** у каждого интерактивного состояния есть переход
      (`hover`, `focus-visible`, `active`, открытие, смена) — длительность из
      `src/styles/motion.css`, а не числом в компоненте.

**Секция:**

- [ ] собрана из компонентов и данных, без самодельных примитивов;
- [ ] высоты и якоря совпадают с эталоном, числа в отчёте;
- [ ] нет переполнения на 390/768/1440;
- [ ] сборка зелёная, консоль пустая;
- [ ] **блок живой:** `npm run interactive` показывает, что нажатия меняют
      состояние. Секция с кнопками, которые ничего не делают, — картинка;
- [ ] **переключатель показывает своё состояние:** бургер стал крестиком,
      шеврон повернулся, стрелка сменилась. Открытие, которое видно только по
      панели, читается как «ничего не произошло»;
- [ ] отчёт с человеческой частью и числами.

## 10. Известные пробелы

Не «норма», а список того, чего нет и что нельзя обойти:

- вёрстка не воспроизводит эффекты: 34 узла с `BACKGROUND_BLUR` (шапка) и 6 с
  `DROP_SHADOW` есть в файле, но не в CSS — `backdrop-filter` и тени не собраны;
- `measure` проверен на одной секции (hero): 8 узлов из 14 размечено,
  обязательные покрыты на 100 %; на остальных 13 секциях — не проверялся;
- G1 не закрыт: из 54 наборов дизайн-системы размечены три (btn-primary,
  arrow-quiet, play);
- `/ds` — страницы со всеми вариантами компонентов — нет;
- адаптив не начат: в файле только 1440, мобильные макеты заказаны;
- на доске 28 старых карточек, ссылающихся на удалённые файлы — их нужно
  архивировать, а не выполнять;
- уставы ролей перенесены в `docs/system/agents/`; копия в `../agent-system/`
  осталась исторической и может расходиться — читать проектную.
