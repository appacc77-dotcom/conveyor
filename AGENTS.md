# AGENTS.md — Syntonia

Читается агентом до любых изменений. Здесь: что является истиной, что можно
трогать и когда работа считается сделанной. Если правило мешает — остановись и
спроси, а не обходи.

## 0. Проект и его состояние

Syntonia — рабочая версия сайта: Astro + обычный CSS + данные, без React,
Tailwind и CMS. Задача — удерживать компонентную дисциплину и проверяемый перенос
Figma → спецификация → компоненты → страницы → проверки.

Состояние на 06.11.2026: собраны все 11 страниц; 27 карточек done, 1 review.
Актуальная сводка — [`STATUS.md`](STATUS.md), перенос — [`docs/PORTABILITY.md`](docs/PORTABILITY.md).
Проект перенесён в самостоятельную папку `syntonia/`: локальные npm-зависимости,
локальный Playwright, smoke без DSH и без соседних репозиториев. Живой канбан DSH
остаётся опциональной интеграцией.

Целевой процесс — [`docs/system/PROCESS.md`](docs/system/PROCESS.md)
(фазы P0–P7, ворота G0–G3). Агентная система — [`docs/system/README.md`](docs/system/README.md).

## 1. Источники истины (по приоритету)

1. `docs/system/figma/decisions.md` — принятые решения. Выше кода.
2. `design/export/home/home-1440.png` — рендер канваса 1:1. Эталон пикселя.
3. `docs/system/figma/tokens.css`, `typography.css` — локальная копия токенов.
4. `public/structure/figma/` — подтверждённые экспорты секций; `design/export/*`
   — полные рендеры.
5. `.fig` — только через `extracted`; версия и хеш обязательны (если используется).
6. Код `src/` — реализация, не истина.

Два правила, которые важнее остальных:

- **Число без версии `.fig` — не число.**
- **Размер из дерева без проверки кропом — не размер.** У 65 узлов масштаб
  сочетается с override: кнопка на карточке практики в дереве 249×44,7, на холсте
  182,6×32,7.

## 2. Принципы переноса

Действуют всегда, в любом режиме.

1. **Единица работы — компонент, единица приёмки — тоже.** Страница — композиция,
   а не поле для подгонки.
2. **Эталон — рендер, не дерево.** Сверяемся с кропом или `home-1440.png`.
3. **Компонент не знает, где стоит.** Ни `width`, ни `margin`, ни `font-size` под
   конкретное место вызова. Если размер не сошёлся — виноват шрифт, трекинг или
   паддинг, а не место вызова.
4. **Только токены.** Hex и «похожий» px в компоненте — дефект. Токены — из
   сгенерированного файла, не набранные руками.
5. **Имена 1:1 с Figma.** Набор `btn-primary` → `btn-primary.astro`. Новые
   компоненты библиотеки — в `src/components/ds/`.
6. **`data-figma-node`** на каждой секции: без него нечего сравнивать.
7. **Не додумываем.** Нет состояния, текста, цены или отступа в макете — значит
   их нет. Вопрос — в `decisions.md`, а не в код.
8. **Мобилка — отдельно.** Макеты 390/768 заказаны. До них адаптив — инженерный
   слой (нет переполнения, тап-таргеты ≥ 44 px), и он не называется «по макету».
9. **Контент-заглушки помечаются.** Цены и длительности из файла не подтверждены
   заказчиком: они допустимы в вёрстке и блокируют публикацию, а не карточку.

## 3. Границы

- **Runtime:** `src/`, `public/`, `astro.config.mjs`, `tsconfig.json`,
  `package.json`. Публикуется `dist/`.
- **Не трогать без карточки:** `design/**` (эталоны), `docs/system/**`
  (процесс и решения), `package.json` (зависимости).
- **Общий слой** — `src/styles/base.css`, `tokens.css`, шапка, подвал — меняется
  отдельной карточкой, а не «попутно».
- **Новые зависимости** — только с согласованием.
- **Git:** один коммит — одна мысль. Не смешивать перенос и правку текста.
  `push`, `reset --hard`, `rebase` — не без просьбы.
- **Не менять** `tokens.css` вручную под конкретную секцию: пока он не
  генерируется, любая правка — отдельная карточка с причиной.

## 4. Задача = карточка

Одна карточка — один запуск. В карточке: `id`, единица (`component` / `section`),
узел Figma, `figma_version`, срез `spec`, кроп, `files:`, команда приёмки,
`content_status`.

- работа начинается только при заполненном Definition of Ready
  ([шаблон](docs/system/templates/card.md));
- меняются только файлы из `files:`; нужен ещё файл — `blocked`, а не расширение
  правки;
- по завершении — отчёт с числами ([шаблон](docs/system/templates/report.md)),
  статус `review`, не `done`;
- карточку в `done` переводит приёмка, не автор.

Доска — внешний DSH Kanban (`DSH_BOARD_URL` или прокси `/kanban`). Перед работой:
`kanban_board { next: true }`; закончил — `kanban_card { action: "move", cardId,
column: "review" }`. `board.json` руками не править: плагин проверяет DoR и
ведёт историю. Как это устроено — [`docs/system/KANBAN.md`](docs/system/KANBAN.md).

## 5. Проверки

Сейчас в проекте есть:

```bash
npm run dev       # http://127.0.0.1:4321/
npm run build     # dist/
npm run smoke     # build + статический сервер + Playwright 1440/390
npm run preview
```

Автоматических ворот пока нет. Это не отменяет проверку — это меняет её форму:
**любое утверждение о соответствии подкрепляется числом и командой**, которая это
число получила. Скриншот без числа — впечатление, а не проверка.

Когда появятся `ds:check` и `page-check` (их делает `docs/system`), они
становятся обязательными: без зелёного прогона работа не принимается.

## 6. Стоп-условия

Остановиться и вернуть `blocked` с причиной, если:

- нет кропа, среза spec или версии `.fig`;
- в `decisions.md` открыт 🔴 по этой единице;
- spec расходится с кропом (тогда чинится spec, а не вёрстка);
- нужен файл вне `files:`;
- три итерации подряд красные по одному и тому же числу;
- чтобы пройти проверку, нужно нарушить §2 — например, вписать ширину.

В отчёте: что отсутствует или противоречит, варианты решения, что уже проверено.
Решает владелец.

## 7. Переходный режим

Пока ворот нет, секции собирать можно — иначе работа встанет. Но режим не отменяет
§2:

- никаких **новых** `width`/`height`/`margin`, подобранных под место вызова;
  семь существующих в `Button.astro` — долг (§10), а не образец. Нужна ширина —
  запись в `decisions.md` с причиной и отдельная карточка;
- новый примитив — только в `src/components/ds/` и с именем из Figma;
- `tokens.css` не правится под секцию;
- каждый обход правила — строка в `decisions.md` с причиной и датой;
- в отчёте — числа: высоты, координаты, пиксельная доля, переполнение;
- «готово» без чисел не существует.

Переход заканчивается, когда `docs/system` даёт `resolve` + `ds:check`:
дальше действует обычный порядок — G1 на компонентах, потом страницы.

Пока `spec` и кропов на все секции нет, их роль для главной играет
`design/export/home/home-1440.png`: секция режется из него по `y`. Недостающие
поля карточки помечаются `n/a` с причиной — это честнее, чем выдуманный DoR.

## 8. Документы: две версии

Правило проекта: у документа две версии — человеческая (что это значит, без имён
свойств) и агентская (id, свойства, было → стало).

- `changes.md` / `changes.agent.md` / `changes.json` — что изменилось в новой
  выгрузке `.fig`;
- `designer-fixes.md` + `.csv` + `.extra.md` — что поправить в макете;
- `decisions.md` — принятые решения, append-only;
- `journal.md` — шаги человеческим языком, для чтения в перерыве;
- `reports/layout/*`, `reports/gates/*` — числа и вердикты.

## 9. Definition of Done

**Компонент:**

- [ ] имя = имя набора Figma, API = пропсы Figma;
- [ ] нет размеров, зависящих от места вызова;
- [ ] только токены;
- [ ] `data-figma-node`;
- [ ] есть в `/ds` во всех вариантах (когда `/ds` появится);
- [ ] кроп-дифф в пороге (когда появится `ds:check`).

**Секция:**

- [ ] собрана из компонентов и данных, без самодельных примитивов;
- [ ] высоты и якоря совпадают с эталоном, числа в отчёте;
- [ ] нет переполнения на 390/768/1440;
- [ ] сборка зелёная, консоль пустая;
- [ ] отчёт с человеческой частью и числами.

## 10. Известный долг

Не «норма», а список того, что нельзя тиражировать:

- `Button.astro`: семь `width` у вариантов кнопки (`btn--hero` 303 px и др.) —
  убрать отдельной карточкой, не «попутно»;
- `tokens.css` набран руками — заменить генератором из кита;
- `/ds` нет — все варианты компонентов негде увидеть разом;
- `spec`/`crops` из кита ещё не подключены к проверкам v2;
- картинки `process` взяты кропами из рендера, без альфы — нужен нормальный экспорт;
- замеры пока ручные, скриптов в `tools/` нет.
