# Профиль прогона: что занимает время

Замер сделан на ветке `verify/full-run-2026-11-11`, 11.11.2026, Mac, холодный
прогон без кэша: `node tools/conveyor.mjs check --all`.

Числа берутся из артефактов, а не по секундомеру на глаз:
`reports/runs/<id>/verdict.json` пишет `ms` для каждого шага, сумма шагов
сверяется с общим временем — разница это накладные расходы конвейера.

## Итог

| | было | стало |
|---|---:|---:|
| полный прогон | 46.8 с | **23.1 с** |
| `interactive` | 24.3 с | **9.2 с** |
| `stretch` | 8.9 с | **1.7 с** |
| накладные конвейера | 0.7 с | 0.7 с |

Кэш не помогает: `check --all --cache` даёт те же ~48 с — в профиле приёмки
ни один шаг не пропускается, кэшировать нечего.

## Шаги по времени

| шаг | время | доля | что делает |
|---|---:|---:|---|
| `interactive` | 9.2 с | 41 % | нажимает все элементы управления на семи страницах |
| `measure` | 5.4 с | 24 % | сверяет геометрию 47 секций |
| `stretch` | 1.7 с | 8 % | сравнивает ширины на 1440 и 1512 |
| `build` | 1.5 с | 7 % | сборка Astro |
| `layout` | 1.1 с | 5 % | горизонтальная прокрутка на ширине макета |
| остальные 17 шагов | ~3.4 с | 15 % | сравнения, реестры, контракты |

Сумма шагов 22.4 с, общее 23.1 с.

## `interactive`: 24.3 → 9.2 с

Разбор по коду и замеру (инструментированная копия, по фазам):

| статья | было | стало |
|---|---:|---:|
| фиксированные паузы | **16.1 с** | 0 |
| клики | 3.8 с | 3.8 с |
| снимки подписи | 2.6 с | 2.6 с |
| ожидание изменения секции | 0.3 с | 0.3 с |

Причина была в `waitForTimeout(150)` после каждого из 113 элементов —
17 секунд независимо от того, есть ли что ждать.

**Что сделано.** Пауза убрана. Подпись переключателя снимается сразу после
клика, и только если она совпала с исходной **при уже переключённом
`aria-expanded`** — то есть элемент собираются обвинить в «меняет лишь
атрибут» — ждём 160 мс и снимаем подпись ещё раз. Платят только
подозрительные элементы, остальные идут дальше сразу.

Почему не ожидание анимаций: пробовал `getAnimations().finished` (29.7 с) и
опрос «подпись перестала меняться» (23.3 с) — оба медленнее, потому что
у нас почти у всех переключателей есть переход 160–450 мс, и ожидание конца
перехода дороже фиксированной паузы. Оба варианта откачены.

**Проверено подменой:** в `dist/index.html` добавлена кнопка, которая меняет
только `aria-expanded`. Ворота видят 114 элементов и **1 «притворяется»** —
то есть класс дефекта по-прежнему ловится. После проверки сборка
восстановлена.

## `stretch`: 8.9 → 1.8 с

Причина была не в работе, а в ожидании сети: на каждой из 14 загрузок
(7 страниц × 2 ширины) стоял `waitUntil: 'networkidle'`, а это 500 мс тишины
сети после загрузки.

**Что сделано:** `load` + `document.fonts.ready`. Шрифты нужны, потому что
дальше меряется ширина текста; после их загрузки ожидание сети ничего не
добавляет.

**Проверено:** шаг зелёный до и после, страниц и проверок столько же;
отдельный замер 8.89 с → 1.74 с.

## `measure`: 5.4 с

47 секций × ~110 мс: загрузка страницы, поиск узлов по `data-figma-node`,
сравнение координат. Здесь нечего чинить одной строкой: время линейно по
числу секций, и это плата за то, что каждая проверяется в браузере.

Если понадобится быстрее — вариант один: одна загрузка страницы на все
секции страницы (сейчас секция = загрузка). Оценка: 47 → 7 загрузок, около
2 с экономии. Не делалось: выигрыш меньше, чем у `stretch`, а правка
трогает главные ворота.

## Как повторить

```bash
node tools/conveyor.mjs check --all      # прогон
node tools/profile.mjs                   # таблица последнего прогона
node tools/profile.mjs --prev            # сравнение с предыдущим
```

`npm run profile` — то же самое.
