Файл для чтения человеком. Агентская версия — `AGENTS.md` и `docs/system/`.
Здесь: как устроено, что уже проверено числами и какие решения приняты.

Обновляется по ходу работы. Последнее обновление — 06.11.2026.

## 1. Что строим

Не сайт, а **конвейер**: живой макет Figma → числа → компоненты → страницы →
проверки. Сайт — побочный продукт; ценность в том, что результат воспроизводим
командой, а не «выглядит похоже».

Предыдущая попытка дала 13 страниц за двое суток и приёмку с **escape rate 33%**:
пять дефектов из пятнадцати карточек нашлись уже после «готово». Причина не в
скорости — в том, что ворот не было ни одних.

## 4. Цикл работы (образец — hero)

1. **Узел.** `exec-js` обход дерева: `read-tree.js` → координаты, размеры,
   авто-раскладка, видимость, тексты, заливки.
2. **Спека.** Числа из дерева → `design/figma/spec/<section>.json`.
3. **Кроп.** `figma-agent export-png --node <id>` → `design/figma/crops/`.
4. **Ассеты.** Фото — по `imageHash` (`getImageByHash().getBytesAsync()`), иконки —
   `exportAsync({format:'SVG'})`. Не рисуются руками.
5. **Сборка.** Компонент из токенов; размеры не вписываются под место вызова.
6. **Замер.** `npm run measure` — геометрия против спеки, exit 1 при Δ > 1 px.
7. **Пиксель.** `npm run compare` — сигнал регрессии, не критерий приёмки.

Правило, которое дало результат на hero: **ширина кнопки не задаётся**. 303 px
получаются из `16 + 249 + 8 + 14 + 16`. Раньше в `Button.astro` стояло
`width: 303px` и ещё семь таких же — и это считалось нормой.

## 5. Модули и инструменты

Конвейер разбит на **четыре крупных модуля**, а не на восемь мелких: мелкие
модули дают свару в каталоге скилов, и агент выбирает не тот.

| Модуль | Фаза | Что делает | Состояние |
|---|---|---|---|
| `figma-intake` | P0–P1 | снимок живого файла: структура, дизайн-система, реальность, дрейф | **готов** |
| `figma-model` | P2–P3 | спека секции, кроп, ассеты, токены | токены готовы, спека руками |
| `section-build` | P4 | сборка компонента по спеке | процедура, скриптов нет |
| `gates` | G1–G2 | `measure` + `compare` | готовы |

Модуль 1 — `npm run intake`:

- проверяет, что мост жив и открыт **тот** файл (`fileName` и `fileKey`);
- снимает `live/{structure,ds,reality}.json`;
- пишет `snapshot.json` с временем, `fileKey` и числом инстансов по страницам;
- **ловит дрейф**: если с прошлого снимка файл правили, печатает, где именно
  изменилось, и предупреждает, что спеки и кропы могли устареть.

Коды возврата: `0` — снято, `1` — открыт другой файл, `2` — мост недоступен,
`3` — скрипт Figma вернул ошибку.

### Команды

| Команда | Что делает | Ворота |
|---|---|---|
| `npm run intake` | снимок живого файла | **да**, exit 1 при чужом файле |
| `npm run ds:tokens` | токены и типографика из живого файла | — |
| `npm run shot -- <sel> <out> <w>` | снимок элемента через Playwright | — |
| `npm run measure -- <spec.json>` | DOM против спеки | **да**, exit 1 при Δ > 1 px |
| `npm run compare -- <crop> <shot>` | пиксельная сверка | сигнал |

`compare` написан на Node с разбором PNG через `zlib` — внешних зависимостей нет
(первая версия требовала Pillow и не запускалась на системном Python).
